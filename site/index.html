What this PR does

    Written, recorded and attached by Codex, told only “please open a pull request for this branch.” Each item ticks as the video reaches the step that proves it.

    Your agent already knows what it changed.

    So it writes the tour. Pro Tour gives it a small, typed tour API, records the result in a real browser with a visible cursor, captions and on-screen checks, and posts it where you review. No model key, no CI setup: it runs on the agent you already use and your gh login.

    The agent writes what the change lets a user see or do, as a checklist, before any step.

    Write the tour

    A short TypeScript file in .tours/, type-checked in a second before anything records.

    pro-tour check
    3

    Record it

    Playwright plays it with a cursor and captions. If a check fails, the agent reads the failure and fixes the tour or the code.

    pro-tour run .tours/x.tour.ts --url …
    4

    Attach it

    One comment on the PR: the video and the checklist. A newer recording hides the older one.

    pro-tour publish

    A video you can believe.

    Anyone can record a demo that looks fine. A tour only passes when its checks prove what each step claims, against the real app, and a failing tour is never posted.

    ✓ Every step

    must change something

    Checks are sampled before the actions and after each one. A step that only asserts what was already on screen fails.

    ✓ Every behavior

    must be shown

    Each item on the checklist is tied to the passing step that demonstrates it. Nothing on the list goes unproven.

    ✓ Every comment

    must come from a passing run

    Failed recordings, and recordings made from an older version of the tour, are refused at publish time.
